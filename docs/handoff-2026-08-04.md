## 1. What shipped

### BDL-006 The Regulator (commit `bcee649`)

A tuning instrument at `/lab/bdl-006`, and an overlay on the home page at `/?tune`. Three sections, three natures of control: a free-spinning crown for color, a stepped switch for spacing that reports rather than sets, and pull-out crowns for texture and motion.

- **The color ramp solves itself.** `src/lib/oklch.ts` computes OKLCH lightness steps with a cosine chroma taper and hue drift (darks toward blue-black, lights toward warm paper), then anchors every stop to a WCAG ratio against the live `--field` rather than to a lightness someone liked. Seeded from the computed `--accent`, re-seeded when the face flips. Six-digit hex throughout, because `draw2d.ts`'s `parseColor` falls back to white on anything else.
- **Setting the grain crown writes nothing.** It prints a diff to paste, in the spirit of the styleguide's Copy tokens button, including the lines that are easy to forget: BarkField's fallback literal, the pattern default, the test that asserts it, and the OG images that quietly take that default.
- **BarkField gained exactly one thing:** a `bark:retune` CustomEvent listener that regenerates dashes at a new grain and calls `setDashes`. Same seed, so it stays the same tree. WebGL path only; the 2D fallback ignores it.
- **Accent green means running.** The crown stem turns accent only while that crown is pulled out. Nothing else in the panel is green.
- Unlisted and noindexed. It is reachable by direct URL, absent from every catalog and the sitemap. That is expressed as a `noindex` flag on the lab schema, which hides an entry from all four listing queries.

Verified in a real browser: retune uploads exact dash counts and rejects malformed payloads; the overlay seeds from the hero's actual density; the ramp hits its targets on both faces.

## 2. Decisions, with reasoning

### CSP: tested and rejected, not deferred

Astro's `experimental.csp` was enabled and verified in a real browser. It passed everywhere except `/styleguide` and `/lab/bdl-002`, which build a `<style>` element at runtime and rewrite its `textContent`. Under hash-based `style-src` the element keeps its text but `.sheet` is null, so nothing applies, **and no console error is raised**. The controls look fine and silently do nothing. `bdl-002` is a public shipped experiment.

Measured, not assumed:

| How a style is set | Under CSP |
|---|---|
| `el.style.setProperty()` (CSSOM) | applies |
| `setAttribute('style', ...)` | blocked |
| `<style>` element with unhashed text | blocked, `.sheet` is null |

BDL-006 passed the gate by luck: Svelte 5 writes reactive `style={...}` bindings through CSSOM. Three hand-authored inline style attributes exist and would need moving before CSP could ship.

Beyond the breakage, it does not pay for itself here: no user-submitted content is rendered anywhere, no third-party scripts, no CDN, no embeds. The contact form does not change that, since submissions are emailed rather than rendered. Full reasoning and the two re-open triggers are in `docs/deploy.md`.

### Permissions-Policy: added, then removed the same day

It shipped as `camera=(), microphone=(), geolocation=()`, then the founder reversed the standing no-permission-prompts rule. Those three block **first-party** use, which would have killed Tonight's Sky and anything like it. Dropped rather than relaxed to `(self)`, because `(self)` protects nothing this site is exposed to.

### The Lab rolls heavy

Founder verdict, verbatim: *"we need to roll heavy in the lab. i wanted to be tentative at first but, within the bounds of 'quiet luxury,' smack people in the face with technical and artistic flex. I hated the experiments because they're paltry and boring. even i can't get excited for that and it's my site. how am i going to explain it to someone who's not 7/8ths as technical as i am"*

Both halves bind: flex hard, stay inside quiet luxury. The test is what a **non-technical** visitor feels in the first five seconds. This is grounds for revisiting shipped pieces, not only for judging new ones. Recorded in `docs/lab-backlog.md` under the 2026-08-03 direction set. **Not yet acted on. Needs its own session.**

**Two caveats, both real as of this writing:**

1. **The analytics beacon is not appearing in the HTML.** Checked cache-busted; `Cache-Control` has no `no-transform`, so that is not the cause. Most likely the edge is serving HTML cached from before it was enabled, or automatic injection does not reach Worker-served assets. Next step: purge cache and recheck. If still absent, embed the snippet manually in `HeadCommon.astro`, which is a one-line change.
2. **Two DMARC records existed simultaneously on 2026-08-04, which disabled DMARC entirely.** A hand-written record and Cloudflare's generated one were both added. Per RFC 7489, a receiver finding more than one record at `_dmarc` must discard the domain's policy and treat it as having none, so two records are strictly worse than either alone. Resolved by deleting the hand-written one and keeping Cloudflare's, which feeds the DMARC Management dashboard. **Verify with `nslookup -type=TXT _dmarc.birchdesignlab.com` and confirm exactly one `v=DMARC1` line.** If both destinations are ever wanted, `rua` takes a comma-separated list inside one record; never a second record.

## 4. Things that will bite if forgotten

- **`npm run deploy` builds from the working tree, not the commit.** The contact form markup sits in a named git stash for exactly this reason. Run `git stash list` before deploying locally.
- **Workers Builds had an outage on 2026-08-03** ("Workers Build Failures", stuck in Initialize for 39 minutes). It recovered. `npm run deploy` bypasses the pipeline if it happens again.
- **`_headers` does not apply to Worker-generated responses.** `/api/contact` is already live and its 405 and error responses ship without `Referrer-Policy` and `X-Frame-Options`. The zone-level toggles now cover nosniff and HSTS there, so it is two headers short rather than four. Fix when the contact form ships.
- **CSP is rejected, not pending.** The spec's 4.1 is stamped with the outcome so nobody rebuilds it from the merged plan.
- **The `.astro/` content-layer store serves stale frontmatter** across dev-server restarts. `rm -rf .astro` and restart. Distinct from `node_modules/.vite` staleness.
